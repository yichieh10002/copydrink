# 共用菜單架構

所有店家使用同一份前台元件，不依「得正／WUWIN」切換不同實作。

| 檔案 | 職責 |
| --- | --- |
| dist/menu-model.js | 分類固定 ID、相容舊資料、同步名稱與標籤、推薦及上架判斷 |
| dist/ui.js | 共用 DOM、按鈕與 Logo 建立函式 |
| dist/menu-view.js | 完整菜單、分類複選、地區複選、價格與複製入口 |
| dist/store-view.js | 店家資訊、品牌介紹、推薦、官網與熱量連結 |
| dist/order.js | 共用商品小抄、杯型容量、複製文字與分享 |
| dist/home-tools.js | 首頁自由填寫與其他工具 |
| dist/app.js | 搜尋、網址、歷史紀錄、頁面狀態與跨店搜尋結果 |
| dist/published-data.js | 已發布文件轉成前台資料；不讀取管理者草稿 |
| dist/cms.js | 管理者操作、儲存、發布與分類管理介面 |

## 分類只在一個地方管理

後台 → 店家 →「菜單分類」：新增／改名、標籤、上移／下移、刪除未使用分類。
商品編輯用下拉選擇分類，不再自行輸入分類文字。

brand.categories 是分類資料來源，每筆包含 id、name、tags。
舊資料的 categoryLabels 可暫存為相容的 label；在分類管理儲存後，輸入的名稱成為正式名稱。
商品使用 categoryId 連到分類，menuCategory 保留同步名稱以相容既有 schema v2。
分類改名不改 ID，標籤、價格及商品關聯會保留。仍有商品使用的分類不能移除。

讀取舊草稿時在記憶體中建立固定分類 ID，直到按儲存才寫回雲端；
不會自動發布或改寫現有正式快照。舊發布版本和還原流程仍可使用。
共用模型同步 brand.menus、categoryTags、categoryLabels，避免各畫面自行維護名稱對應。

## 店家差異放資料

- 甜度、冰量／溫熱、配料、杯型由店家設定；商品只選適用杯型與價格。
- 特殊製作規則仍是備註，不強制限制甜度或冰量。
- 介紹留空不顯示；推薦預設收合；只有一個地區時不顯示地區選擇。
- 多個啟用地區時，完整菜單上方顯示共用地區複選按鈕。
- 完整菜單不套用已隱藏舊查詢介面的熱量／溫度等條件，避免記住的舊條件讓商品消失。
- 每家店獨立儲存與發布；修改分類或價格不需要部署網站。

## 驗證

tests/shared-menu.cjs 驗證分類改名保留 ID／標籤／價格、舊文件不被原地改寫、
兩家店使用相同菜單、分類篩選、詳細及複製入口。
tests/cms-flow.cjs 驗證分類後台改名及商品下拉，再接儲存／發布流程。
tests/published-data.cjs 驗證發布轉換保留分類關聯、地區價格與其他店家的資料。

## copydrink 外觀與搜尋

- `theme.js` 在頁面顯示前讀取獨立的 `copydrink-theme` 偏好（預設淺色），以 `data-theme` 和 CSS 色彩變數切換。儲存不可用時仍可切換，不需要 API；管理後台不載入此主題。
- 店家頁的同一個搜尋欄移到 Menu 標題後、分類導覽前。`menuParts` 保留搜尋容器，重新篩選只更新標題與結果，避免移除正在輸入或組字的欄位。返回首頁後再搬回原處。
- `tests/theme.cjs` 驗證偏好恢復、儲存、跨分頁與儲存失敗；`tests/shared-menu.cjs` 補上搜尋節點保留及位置切換測試。
